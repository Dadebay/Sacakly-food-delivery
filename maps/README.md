# Локальный OpenStreetMap для AlowAlow

Этот отдельно разворачиваемый сервис самостоятельно отдаёт базовую карту
Туркменистана веб-клиентам и мобильным приложениям и не использует публичные
тайлы `tile.openstreetmap.org` во время работы. Он состоит из:

- ежедневного Shortbread MBTiles-экстракта Geofabrik;
- локального насыщенного стиля VersaTiles Colorful, спрайтов и двух Noto Sans
  шрифтов;
- TileServer GL 5.6.0, который отдаёт MapLibre style/vector tiles и
  совместимые PNG XYZ для существующих Leaflet-карт.

TileServer не получает и не хранит координаты курьеров, заказы, телефоны или
другие операционные данные. Он отдаёт только статический фон карты. GPS-точки
идут с приложения курьера в NestJS API, хранятся в Redis и накладываются
клиентом поверх карты как динамические маркеры.

## Запуск

Docker Desktop должен быть запущен. Первый запуск скачивает около 275 МБ
исходных архивов и Docker image TileServer GL. После подготовки локальные
данные занимают около 155 МБ, распакованный image — около 873 МБ, поэтому
нужно оставить не менее 1,2 ГБ свободного диска:

```bash
npm run maps:up
```

Проверка:

```bash
curl --fail http://127.0.0.1:8080/health
curl --fail --output /tmp/alowalow-map-tile.png \
  http://127.0.0.1:8080/styles/alowalow/10/677/395.png
```

Endpoints:

- preview: `http://127.0.0.1:8080/`;
- необязательный MapLibre style для продвинутых клиентов:
  `http://127.0.0.1:8080/styles/alowalow/style.json`;
- Leaflet XYZ: `http://127.0.0.1:8080/styles/alowalow/{z}/{x}/{y}.png`;
- vector TileJSON: `http://127.0.0.1:8080/data/turkmenistan.json`;
- raw vector PBF: `http://127.0.0.1:8080/data/turkmenistan/{z}/{x}/{y}.pbf`;
- healthcheck: `http://127.0.0.1:8080/health`.

Для текущего мобильного клиента выбран PNG XYZ: в production Nginx публикует
его как `/tile/{z}/{x}/{y}.png`. Это готовый растровый фрагмент дорог и подписей
Туркменистана; он никак не связан с точностью или частотой GPS курьера. Один
TileServer GL поддерживает PNG и необязательный MapLibre style, поэтому второй
стек карты для мобильного приложения не нужен.

## Подключение мобильного устройства в локальной сети

По умолчанию порт безопасно слушает только `127.0.0.1`. Чтобы реальный телефон
в той же Wi-Fi сети увидел карту, запустите сервис на LAN-интерфейсе и явно
разрешите IP компьютера:

```bash
MAP_BIND_ADDRESS=0.0.0.0 \
MAP_ALLOWED_HOSTS=localhost,127.0.0.1,192.168.1.20 \
npm run maps:up
```

Замените `192.168.1.20` на LAN IP компьютера. Мобильное приложение использует
`http://192.168.1.20:8080/styles/alowalow/{z}/{x}/{y}.png`. Не открывайте этот порт
в Интернет на рабочем ноутбуке; ограничьте его локальной сетью firewall.

В DEV/PROD это отдельный Compose service (или отдельная машина позднее) с
постоянным URL. Один и тот же URL используют мобильные приложения и веб. На
первом этапе TileServer может жить на одном физическом сервере с API, если
хватает RAM, но его контейнер, данные и порт остаются изолированными. Публичный
доступ лучше выдавать через reverse proxy/TLS; координаты курьеров всё равно
передаются только в защищённый NestJS API.

После запуска карты можно запускать API и админку обычной командой
`npm run dev`. Значение в `apps/admin/.env.example` уже указывает на этот
локальный XYZ endpoint.

## Обновление карты

Чтобы атомарно скачать свежий экстракт Туркменистана и перезапустить сервер:

```bash
npm run maps:update
```

Если загрузка оборвалась, повторный запуск продолжит `.part`-файл. Новая карта
заменяет рабочий MBTiles только после проверки SQLite-заголовка и размера.
Версии стиля и шрифтов закреплены, а их release-архивы проверяются по SHA-256
до распаковки.

## Остановка

```bash
npm run maps:down
```

По умолчанию контейнер публикуется только на `127.0.0.1`, работает без Linux
capabilities, с read-only root filesystem и лимитом 1 ГБ RAM. Для LAN-доступа
адрес прослушивания меняется явно через `MAP_BIND_ADDRESS`. Загруженные данные
лежат в `maps/runtime/`, не коммитятся и не удаляются при остановке.

На локальной проверке после первого рендера контейнер использовал примерно
255 МБ RAM; лимит 1 ГБ оставлен для кратковременных пиков параллельного
рендеринга.

Это только базовая карта. Построение маршрутов выполняет отдельный приватный
OSRM из `routing/`, а NestJS отдаёт его результат авторизованному курьеру.
TileServer по-прежнему не получает GPS, заказы или данные клиента.
