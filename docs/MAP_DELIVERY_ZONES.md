# Тарифные зоны доставки на карте

## Зачем это нужно

Названия районов от reverse geocoding отличаются по языку, написанию и
детализации. Они остаются полезным адресом для курьера, но не должны определять
деньги. Тариф выбирается сервером по координатам маркера и сохранённой границе
зоны.

## Настройка в админке

Страница **Тарифы доставки** (`/delivery`) показывает все готовые зоны на одной
карте. Основной сценарий начинается с карты, а не со старого справочника:
администратор нажимает **Выбрать район на карте**, выбирает замкнутую область
(например, город Аркадаг), проверяет полученный контур и задаёт цену. Если в
старом справочнике уже есть строка с тем же названием и велаятом, интерфейс
переиспользует её вместо создания дубликата. Служебная привязка к велаяту
подбирается по ответу геокодера и скрыта в дополнительных полях.

Административные границы этрапов на экран не выводятся: карта показывает
только сохранённые тарифные зоны и текущий редактируемый черновик. Улицы и их
подписи входят в локальный слой карты. Улица является линией, поэтому для цены
администратор обводит замкнутую область обслуживания вокруг нужного участка.

1. Нажмите **Выбрать район на карте** и один раз нажмите внутри выделенного
   района/города либо нажмите уже сохранённый сплошной полигон.
2. Backend запросит настроенный Nominatim, откроет найденную районную зону и
   загрузит её замкнутую границу.
3. Укажите дневную и ночную цену.
4. Чтобы заменить автоматический результат из редактора, нажмите
   **Определить зону по карте**, затем один раз нажмите внутри нужного района.
   Backend запросит настроенный
   Nominatim: найденные названия заполнят поля, а OSM Polygon/MultiPolygon станет
   черновиком границы. Браузер не обращается к Nominatim напрямую.
5. Если OSM знает название, но не содержит замкнутой границы, редактор создаёт
   несохранённый восьмиугольный черновик радиусом примерно 800 метров вокруг
   выбранной точки. Это не официальная граница и не готовый тариф: перед
   сохранением администратор растягивает пронумерованные точки по реальному
   контуру. Если Nominatim не вернул даже подходящее название, такой же
   черновик всё равно создаётся, а названия заполняются вручную. Клик рядом со
   стороной вставляет новую точку именно в эту часть полигона; допускается от 3
   до 64 точек. Последнюю точку с первой соединяет интерфейс. Любую точку можно
   перетащить мышью или касанием.
6. Кнопки **Уменьшить** и **Увеличить** масштабируют весь контур относительно
   его центра. **Отменить точку** удаляет последнюю добавленную точку, а
   **Очистить границу** переводит район обратно в состояние без зоны.
7. Сохраните район. Backend отклонит самопересечение или пересечение площади с
   другой включённой зоной. Общая граница соседних районов допустима.
8. Когда есть хотя бы одна включённая проверенная тарифная зона, включите
   **Определять тариф только по карте** в блоке резервного тарифа.

Ежедневная таблица под картой показывает только районы, у которых уже сохранён
реальный полигон. Старые строки административного справочника без контура не
выдаются за готовые тарифные районы: они остаются для автоматического
переиспользования, совместимости и отката текстового режима.

Автоматический результат — только редактируемая подсказка. Администратор
проверяет название и геометрию перед сохранением; цена и включение доставки не
берутся из OSM. Если Nominatim вернул составную границу, выбирается часть,
содержащая нажатую точку, а если это невозможно — самая крупная часть.
Крупная административная граница этрапа не импортируется как внутренняя
тарифная зона и не показывается отдельным слоем.

Переключатель версионирован. При одновременном редактировании устаревшее
сохранение вернёт `409`, после чего конфигурацию надо перезагрузить.

## Серверное поведение

- `mapPricingEnabled=false`: временно сохраняется прежнее однозначное
  сопоставление названия района из reverse geocoding.
- `mapPricingEnabled=true`: `POST /api/v1/delivery/quote` выбирает район только
  через point-in-polygon. Текст адреса не участвует в цене.
- Точка вне всех зон получает резервный дневной/ночной тариф и
  `matchSource=FALLBACK`.
- Точка внутри ровно одной зоны получает её тариф и
  `matchSource=MAP_ZONE`.
- Неоднозначная граничная точка не выбирает случайную дешёвую зону и получает
  резервный тариф.
- При создании заказа и администраторском редактировании backend повторно
  определяет зону по координатам. Переданный клиентом устаревший или
  подменённый `deliveryEtrapId` не влияет на итог.
- `POST /api/v1/delivery/admin/zone-suggestion` доступен только сотруднику с
  правом страницы доставки (`ADMIN`/`SUPER_ADMIN` или назначенная политика),
  принимает одну точку и возвращает локализованные названия плюс не более 64
  точек редактируемой OSM-границы. Запрос ограничен координатами Туркменистана.
- При включённом расчёте по карте старые включённые строки справочника без
  полигона не участвуют в координатном совпадении. Новую включённую тарифную
  зону без валидного полигона сохранить нельзя.

## Мобильное приложение

Мобильное приложение продолжает ставить маркер и вызывать
`POST /api/v1/delivery/quote` с `latitude`, `longitude` и `subtotal`. Из ответа
оно показывает `addressLine`, `fee`, название найденного района и состояние
резервного тарифа. Локальной таблицы районов, цен или проверки адресной строки
быть не должно.

Для предварительного `POST /api/v1/orders/quote` координаты можно передать
дополнительными полями `latitude` и `longitude`. Финальный `POST
/api/v1/orders` всё равно повторно проверяет координаты сохранённого/нового
адреса и остаётся источником истины.

После перемещения маркера клиент должен очистить предыдущую цену и район,
показать загрузку и принять только ответ, соответствующий текущей паре
координат.
