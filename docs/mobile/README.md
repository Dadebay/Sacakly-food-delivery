# Saçakly: передача мобильной команде

**Актуально на 2026-10-06.** Планируются два отдельных мобильных приложения:

1. [Клиентское приложение](CUSTOMER_APP.md) — выбор кафе, заказ и его история.
2. [Приложение курьера](COURIER_APP.md) — заявка, внешние предложения и собственные доставки кафе.

Кафе, кухня и платформенный OWNER работают в отдельных веб-интерфейсах; третье мобильное приложение для них сейчас не планируется. Клиентский [Next.js сайт](../../apps/web) уже служит рабочим примером выбора кафе и оформления заказа. Импортированное старое мобильное приложение не является выпуском Saçakly.

Порядок подключения кафе и границы его данных описаны в [CAFE_ONBOARDING.md](../CAFE_ONBOARDING.md).

## Общий контракт

- Источник поведения: [контекст проекта](../PROJECT_CONTEXT.md), затем [Prisma](../../apps/api/prisma/schema.prisma), [политика статусов](../../apps/api/src/orders/order-policy.ts), контроллеры/DTO API и сгенерированный [OpenAPI](../../apps/api/openapi.json). При расхождении уточнять по серверу, не копировать правила из интерфейса.
- Базовый путь API: `/api/v1`. Адрес production API ещё не назначен; локально API слушает порт 4000. Не подключать приложения к старому A7 серверу или его Firebase проекту.
- Авторизация: OTP по телефону через `/auth/otp/request` и `/auth/otp/verify`; затем `Authorization: Bearer <accessToken>`. `/auth/refresh` ротирует refresh token, `/auth/logout` отзывает его. Refresh token хранить только в защищённом хранилище ОС, обновление выполнять один раз при параллельных 401.
- Push: Firebase FCM. После входа и при обновлении токена вызывать `PUT /notifications/devices` с `installationId` **равным FCM registration token**, `platform: ANDROID | IOS`, необязательными `appVersion` и `locale`. При выходе — `DELETE /notifications/devices/:installationId`, затем logout. Push служит сигналом обновить данные с API, а не источником статуса заказа.
- Поддержать `tk`, `ru`, `en`; значения enum и деньги брать из API, локализовать только отображение. Основные цвета: `#14523b`, `#dbe9d5`, `#c9473d`, `#f7f5eb`.
- Ошибки: 401 — однократный refresh и повтор запроса; 403 — нет права/активного модуля; 404 — ресурс недоступен в текущем контексте; 409 — предложение уже взял другой курьер, изменился заказ или повторный idempotency key с другим телом. После 409 перечитать состояние с сервера. Не вычислять цену или разрешения в приложении.

## Выпуск и границы

Существующие API позволяют собрать часть клиентского сценария и принять внешнее предложение курьером. **Полный выпуск двух приложений пока заблокирован**: новые tenant-safe API для деталей назначенного заказа, курьерского рабочего цикла и отслеживания клиента ещё требуют проектирования и проверки. Старые `/orders/*` и `/tracking/*` нельзя автоматически считать безопасным контрактом для независимых кафе. Перечень по каждому приложению дан в отдельных файлах.

Для каждого нового API нужны тесты разрешённой и запрещённой роли, чужого кафе, гонки/повтора и актуализированный OpenAPI. Мобильные E2E должны проходить на отдельной тестовой базе, без A7 данных.
