# Общие push A7-tagam без регистрации

Текст для команды клиентского мобильного приложения Android/iOS.

Используем **FCM topic `a7-tagam`**, точно в таком написании, без `/topics/`.
Это публичные объявления всем подписанным установкам клиентского приложения:
и гостям, и пользователям после входа. Номер телефона, JWT и запись PushDevice
для этой подписки не нужны. Firebase-проект остаётся `alowalow-c3a21`.

## Что нужно сделать в приложении

1. Заменить старый `broadcastTopic = 'hantagam'` на `'a7-tagam'`.
2. После инициализации Firebase Messaging подписать установку **до login/OTP**:
   `await FirebaseMessaging.instance.subscribeToTopic('a7-tagam');`.
   На iOS сначала дождаться готовности APNs token согласно настройке Firebase.
   Запрос разрешения на уведомления остаётся в принятом приложением flow.
3. Синхронизировать подписку при каждом запуске и после обновления FCM token
   (`onTokenRefresh`). Ошибка сети не должна мешать открытию приложения:
   повторять с ограниченной задержкой/backoff при восстановлении сети или
   следующем запуске. Не считать подписку успешной до завершения SDK-вызова.
4. После успешной подписки на `a7-tagam` отписать установку от старого
   `hantagam`. Не делать две отправки в старый и новый топик: это даёт дубли.
5. **Не отписываться от `a7-tagam` при logout.** Гость продолжает получать
   публичные объявления. Пользовательское отключение уведомлений соблюдать.
6. Сохранить существующий персональный flow: после login регистрировать FCM
   token через `PUT /api/v1/notifications/devices`, при logout деактивировать
   через `DELETE` до удаления JWT. Гостям этот защищённый endpoint не вызывать.
7. Использовать Android default channel `alowalow_orders` в манифесте; backend
   не навязывает `channelId`. На iOS проверить APNs key/capabilities и разрешения;
   сообщение содержит стандартный звук APNs.

## Payload и открытие уведомления

Backend отправляет один общий message:

```json
{
  "topic": "a7-tagam",
  "notification": {
    "title": "Новое меню",
    "body": "Посмотрите новые блюда в приложении"
  },
  "data": {
    "campaignId": "<UUID кампании>",
    "deepLink": "/catalog"
  }
}
```

Все `data`-значения — строки. `deepLink` необязателен; `/catalog` здесь пример,
его надо сопоставить с реальным маршрутом приложения. Разрешать только известные
внутренние экраны; неизвестный/внешний маршрут игнорировать и открывать главный
экран. Если выбранный экран требует входа, пройти обычный login flow.

- При foreground показать уведомление через существующий обработчик.
- В background/terminated стандартный notification показывает система;
  не создавать поверх него второй локальный push.
- Обработать нажатие через `onMessageOpenedApp` и `getInitialMessage()`.
- Использовать `campaignId` как стабильный ключ дедупликации общего объявления
  и обработки нажатия. При повторной отправке кампании он не меняется.
  Системный показ в background нельзя считать гарантированно exactly-once.
- У такого сообщения **нет персонального `notificationId` и записи в inbox**.
  Не отправлять для него `/notifications/me/:id/read` и не увеличивать серверный
  unread count. Персональные сообщения продолжают использовать свой inbox.

## Проверка с мобильщиком

1. Установить новую сборку начисто, разрешить уведомления и **не входить**.
2. Убедиться в успешном SDK-вызове подписки на `a7-tagam`; токен в общие логи
   и чат не выводить.
3. Согласовать конкретное тестовое объявление. Администратор отправляет его
   через «Уведомления → Новая рассылка → Все устройства, включая гостей».
   Это реальная рассылка всем подписчикам, а не одному тестовому телефону.
4. Проверить получение без регистрации в foreground, background и при холодном
   запуске; на Android проверить также разрешение Android 13+, на iOS — физический
   iPhone. Force-stop Android пользователем отличается от обычного закрытия.
5. Войти, выйти и убедиться, что публичные объявления продолжают приходить,
   а персональные сообщения прежнего аккаунта после logout не приходят.
6. Проверить запуск без сети, восстановление подписки, обработку нажатия и
   отсутствие дублей локального/системного уведомления.

## Что означает результат в админке

`SENT` / «Принято к отправке» означает, что Firebase принял сообщение. Firebase
не возвращает число подписчиков, доставившихся устройств или прочтений топика;
счётчики для этой аудитории — `null`. Гости не создаются в таблице пользователей.
Отправлять только общие объявления без персональных данных.

Старые сборки, подписанные только на `hantagam`, новую рассылку не получат:
нужен выпуск мобильной сборки с подпиской на `a7-tagam`. До совместного теста
на телефоне фактическую доставку считать непроверенной.
