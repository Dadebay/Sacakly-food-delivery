# Скидки и баллы: Dev Notes — 2026-10-06

http://127.0.0.1:5174 — кабинет кафе/OWNER; http://127.0.0.1:3000/ru — покупатель.
Опубликованного стенда нет. Запуск: [PLAYWRIGHT_E2E.md](PLAYWRIGHT_E2E.md).

Проверить:
- OWNER включает MARKETING и LOYALTY отдельно в каждом кафе; сотрудник не может включить их сам.
- ADMIN создаёт/изменяет процентную и фиксированную акцию, код, срок, минимальную сумму, максимальную скидку и лимиты. Чужое кафе и OPERATOR получают отказ; устаревшая версия даёт 409.
- Без промокода работает лучшая автоматическая акция. Код заменяет её. Общий и персональный лимит выдерживают одновременные заказы. Quote не расходует лимит.
- В меню можно задать 0 баллов. Баланс кафе A не доступен для подарков кафе B; legacy-баланс не смешивается с новыми кошельками.
- Подарок списывает баланс и остаток только вместе с успешным заказом. Повтор idempotency key не создаёт второе списание.
- Баллы начисляются после доставки; отключение модуля после оформления не отменяет обещание. Отмена возвращает подарок и баллы; повторная отмена ничего не начисляет второй раз.
- Возврат уже потраченного начисления может дать отрицательный баланс. Обычный заказ остаётся доступен, новые подарки — только при достаточном балансе.
- Изменение количества, кода, подарков или адреса сбрасывает quote; во время запроса поля заблокированы. Смена кафе или аккаунта сбрасывает локальный checkout.
- Сотрудник видит скидку и подарок в заказе; без отметки упаковки подарка готовность не подтверждается. Ошибка оставляет список заказов доступным для исправления.
- tk/ru/en, desktop и viewport 390 × 844: доступность форм, фокус, переносы и отсутствие горизонтального переполнения.

## Проверки

Точные результаты финального прогона находятся в [CHANGELOG.md](CHANGELOG.md).
API HTTP-тесты проверяют права, scope, лимиты, конкурентное списание, версии,
начисление/возврат и переполнение целочисленных баллов. Playwright использует
настоящие формы и API. Тестовые начальные балансы заданы фикстурой; полный
цикл начисления через переход доставки проверяется HTTP-тестами.

Скриншоты `rewards-merchant-mobile.png` и `rewards-checkout-mobile.png` сохраняются
в игнорируемой `test-results/`. Проверяются браузерная консоль, runtime и
hydration. Разрешены только прежние конкретные localhost предупреждения Firefox
и ожидаемый 403 OWNER-probe обычного сотрудника в WebKit.

Новых библиотек нет. Кошелёк не polling-ится; состояние перечитывается при
открытии checkout. Персональное использование акций загружается одним groupBy
для кандидатов, без отдельного запроса на каждую акцию. Нет циклов импортов
в 24 web и 13 merchant исходных модулях. Финальная сборка кабинета:
268,83 kB JavaScript / 77,42 kB gzip; CSS 18,17 kB / 4,48 kB gzip.

## Ограничения

Браузерные движки Playwright не заменяют проверку физических iOS/Android.
Native-клиенты получают обновлённую спецификацию, но не новый релиз приложения.
Подарки печатаются на основном внутреннем чеке; отдельная маршрутизация каждого
подарка на кухонный принтер не добавлена. Физическую печать проверяют в кафе.
Платформа ещё имеет ограничения запуска из [ROADMAP.md](ROADMAP.md).
