# Дневной и ночной тариф доставки

Ночью применяется отдельный прайс, а не надбавка к дневному тарифу.
Настройки находятся в админке на странице **Тарифы доставки** (`/delivery`).

## Настройка

1. В карточке «Ночной тариф» задайте начало и конец по времени Ашхабада.
   Начало включено в ночной период, конец относится к дневному. Интервал
   может переходить через полночь; одинаковые начало и конец недопустимы.
2. В каждом районе задайте дневную и ночную цены и отдельные пороги бесплатной
   доставки. Пустой ночной порог означает, что ночью доставка всегда платная.
3. В «Настройке» задайте такие же значения для резервного тарифа — адресов без
   определённого района.
4. Включите ночной тариф и сохраните расписание.

Изначально режим выключен. Миграция копирует действующие дневные цены и пороги
в ночные поля, поэтому сама по себе не повышает стоимость. Неактивное расписание
по умолчанию — 23:00–07:00, часовой пояс всегда `Asia/Ashgabat`.

Изменения доступны ADMIN и SUPER_ADMIN, журналируются и защищены версией.
Если другой администратор успел изменить настройку, API возвращает 409;
нужно обновить данные и повторить изменение. Дневные обновления старых клиентов
без версии продолжают работать.

## API конфигурации

`GET /api/v1/delivery/config` — публичные включённые районы.
`GET /api/v1/delivery/admin/config` — полный справочник для администратора.

Дополнительные общие поля:

- `version`, `nightTariffEnabled`, `nightStartsAt`, `nightEndsAt`, `timeZone`;
- `fallbackNightPrice`, `fallbackNightFreeDeliveryThreshold`.

В каждом районе: `version`, `nightPrice`, `nightFreeDeliveryThreshold`.
`price` и `freeDeliveryThreshold` остаются дневными значениями. Нельзя считать
ночную стоимость только по этим двум дневным полям.

`PATCH /api/v1/delivery/admin/settings` меняет общие настройки. Например:

```json
{
  "version": 1,
  "nightTariffEnabled": true,
  "nightStartsAt": "23:00",
  "nightEndsAt": "07:00",
  "fallbackNightPrice": 30,
  "fallbackNightFreeDeliveryThreshold": null
}
```

Это пример конфигурации, а не принятые рабочие цены. Передайте актуальную версию
из GET. Для `PATCH /delivery/admin/etraps/:id` аналогично передаются `version`,
`nightPrice` и `nightFreeDeliveryThreshold`. Новый район без этих двух полей
получает копии собственного дневного тарифа.

## Расчёт для мобильного приложения

Для новой точки используйте существующий `POST /api/v1/delivery/quote` с
`latitude`, `longitude` и `subtotal`. Для сохранённого адреса с известным
районом используйте `POST /api/v1/delivery/tariff-quote`:

```json
{ "deliveryEtrapId": 25, "subtotal": 120 }
```

Если район не определён, передайте `deliveryEtrapId: null` или опустите поле.
Оба метода возвращают выбранный сервером тариф:

```json
{
  "tariff": "NIGHT",
  "timeZone": "Asia/Ashgabat",
  "validUntil": "2026-09-13T02:00:00.000Z",
  "subtotal": 120,
  "price": 30,
  "freeDeliveryThreshold": null,
  "fee": 30,
  "etrap": null
}
```

Пример выше иллюстрирует ночной резервный тариф с окончанием в 07:00 Ашхабада.
`fee` — сумма к оплате за доставку, `price` — выбранная дневная/ночная цена до
проверки бесплатного порога. Если режим выключен, `tariff` равен `DAY`,
`validUntil` равен `null`. Обновляйте предварительный расчёт при изменении
адреса/суммы, возвращении в оформление и при наступлении `validUntil`.
Веб-админка обновляет активную котировку на этой границе, без фонового опроса
при выключенном ночном режиме или скрытой вкладке.

При создании заказа backend заново проверяет цены. Отображайте `deliveryFee`
и `total` из ответа; клиент не передаёт своё время или итоговые суммы.
При промокодах используйте `/orders/quote` для окончательного расчёта корзины.
Проверка порога остаётся на сумме блюд до скидки, как и для дневного тарифа.

## Уже созданные заказы

Стоимость доставки фиксируется в заказе и используется в чеке. Наступление
ночи, утра или изменение конфигурации автоматически старые заказы не меняет.
Разрешённое администратору редактирование заказа до выдачи курьеру пересчитывает
его по действующей конфигурации, но выбирает временной период по исходному
`createdAt`, а не по времени редактирования. Мобильные Android-проекты находятся
отдельно; этот backend/admin PR не меняет APK.
