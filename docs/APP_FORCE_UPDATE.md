# Версии мобильного приложения

Мобильный контракт из переданного `APP_FORCE_UPDATE.md` реализован в NestJS
и админке. Мобильные приложения находятся в отдельных репозиториях.

## Публичная проверка

```http
GET /api/v1/app/version?platform=ANDROID
```

Без авторизации. Обязательная платформа — строго `ANDROID` или `IOS`.
Ответ настроенной платформы (`Cache-Control: no-store`):

```json
{
  "latestVersion": "1.4.0",
  "minSupportedVersion": "1.2.0",
  "storeUrl": "https://play.google.com/store/apps/details?id=com.gurbanov.alowalow",
  "releaseNotesRu": "Что нового",
  "releaseNotesTk": null
}
```

Версии в примере условные. Сервер не подставляет их при установке.
Версия — `MAJOR.MINOR.PATCH` (до 32 символов), без `+build` или prerelease.
Сравнение числовое: `1.10.0 > 1.9.3`. Минимальная версия не выше последней.
`releaseNotesRu` и `releaseNotesTk` возвращаются строкой или `null`.

Платформа без настройки возвращает **404**. Это означает обычный запуск без
предложения обновиться. По мобильному контракту так же обрабатываются сеть,
ошибочный JSON и остальные ошибки проверки. Миграция не создаёт политик и не
блокирует существующих пользователей. Политику нельзя считать механизмом
авторизации: сам API не блокирует запросы по версии клиента.

## Настройка в админке

Адрес: `/settings/app-versions`, пункт «Настройки», экран «Версии приложения».
Доступ: только `ADMIN` и `SUPER_ADMIN`. Android и iOS сохраняются независимо.

1. Дождитесь публикации и завершения поэтапной раскатки. Проверьте доступность
   версии в магазине для всех пользователей целевой платформы.
2. Укажите последнюю версию и текущую минимальную, ссылку на магазин,
   необязательное описание RU/TK (до 5000 символов каждое).
3. Подтвердите доступность релиза флажком и сохраните.
4. Повышайте минимум только при несовместимом API, критическом баге или другой
   необходимости прекратить работу старых сборок. Обычным новым функциям
   достаточно повышения последней версии.
5. При повышении минимума подтвердите отдельное предупреждение о блокировке.
   Отмена или Escape ничего не сохраняют. Первое сохранение с минимумом выше
   `0.0.0` также требует подтверждения.

В случае ошибки можно уменьшить минимум и исправить ссылку без мобильного
релиза. Верификация публикации — ответственность администратора; сервер
сохраняет подтверждение в аудите, но не проверяет каталоги магазинов автоматически.

Android: HTTPS-ссылка `play.google.com/store/apps/details` с
`id=com.gurbanov.alowalow`. iOS: HTTPS-ссылка `apps.apple.com` с настоящим
числовым `id`. Пока Apple ID неизвестен, оставьте платформу ненастроенной.
Подставные Apple ID и незавершённые релизы нельзя использовать для блокировки.

## Административный API

```http
GET /api/v1/app/admin/versions
Authorization: Bearer <administrator-access-token>
```

Возвращает массив настроенных платформ, включая `platform`, `version`,
`createdAt`, `updatedAt` и публичные поля. Пустой массив — ничего не настроено.

```http
PUT /api/v1/app/admin/versions/ANDROID
Authorization: Bearer <administrator-access-token>
Content-Type: application/json

{
  "latestVersion": "1.4.0",
  "minSupportedVersion": "1.2.0",
  "storeUrl": "https://play.google.com/store/apps/details?id=com.gurbanov.alowalow",
  "releaseNotesRu": null,
  "releaseNotesTk": null,
  "version": 0,
  "publishedConfirmed": true,
  "confirmMinimumIncrease": true
}
```

`version: 0` — создание, иначе последнее значение из административного GET.
Каждое сохранение увеличивает его. `409` требует обновления данных и повторного
внесения изменений. Две одновременные записи не могут перезаписать друг друга.
Изменение политики и `AuditLog` (`app_version.saved`) сохраняются в одной
транзакции: актор, время, платформа, предыдущие/новые значения, подтверждения.
`publishedConfirmed: true` обязателен при каждом сохранении;
`confirmMinimumIncrease: true` — при повышении минимума.

## Проверка перед мобильным релизом

На отдельном локальном окружении и реальном телефоне проверить:

1. Текущая версия не ниже последней — обычный запуск.
2. Текущая между минимумом и последней — закрываемое предложение обновиться.
3. Текущая ниже минимума — блокирующий экран, без «назад» и «позже».
4. «Обновить» открывает правильную страницу магазина.
5. Ошибка сети/404/некорректный ответ — обычный запуск.

Backend HTTP-тесты проверяют контракт, обе платформы, роли, валидацию,
конкурентность, аудит и восстановление снижением минимума. Браузерные проверки
админки не заменяют проверку мобильного экрана и открытия магазина на телефоне.
